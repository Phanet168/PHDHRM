# 03) គោលនយោបាយ និងការកំណត់ស្តង់ដារ

## A. គោលការណ៍វត្តមានស្តង់ដារ

ថ្ងៃនីមួយៗ = បញ្ជីវគ្គ (session) ដែលត្រូវស្កេនចូល/ចេញ។ មានតែ ៣ យ៉ាងប៉ុណ្ណោះដែលត្រូវកំណត់៖

| | អ្វី | កំណត់នៅ | អនុវត្តចំពោះ |
|---|---|---|---|
| ១ | **ម៉ោងគោល** — ព្រឹក + ល្ងាច (ស្កេន ៤ ដង) | ម៉ោងធ្វើការ (`/hr/shifts`) មួយអង្គភាពមួយ | បុគ្គលិកទាំងអស់ នៅថ្ងៃធ្វើការ |
| ២ | **វេនយាម** — ឧ. យាមយប់ ១៧:០០–០៧:០០ ឬ ២៤ម៉ោង | ម៉ោងធ្វើការ (ប្រភេទ «វេនយាម») + តារាងវេនយាម | តែមន្ទីរពេទ្យ/មណ្ឌលសុខភាព តាមអ្នកដែលបានចាត់តាំង |
| ៣ | **ថ្ងៃឈប់/បុណ្យ** | ប្រតិទិនថ្ងៃឈប់ ឬ តារាងវេនយាម (OFF) | មិនតម្រូវវត្តមាន |

ច្បាប់គណនា៖

1. **មន្ទីរសុខាភិបាល / ការិយាល័យស្រុកប្រតិបត្តិ**៖ មានតែម៉ោងគោល។ ស្កេន ៤ ដង៖ ចូលព្រឹក ចេញព្រឹក ចូលល្ងាច ចេញល្ងាច។ មិនអាចបង្កើតវេនយាមបានទេ។
2. **មន្ទីរពេទ្យ / មណ្ឌលសុខភាព**៖ ម៉ោងគោលដូចគ្នា + វេនយាម**បូកបន្ថែម**សម្រាប់អ្នកដែលមានឈ្មោះក្នុងតារាងវេនយាមថ្ងៃនោះ៖
   - ថ្ងៃធ្វើការ៖ ព្រឹក + ល្ងាច + វេនយាម (ឧ. អ្នកយាមយប់ថ្ងៃច័ន្ទ ត្រូវធ្វើការថ្ងៃច័ន្ទផង)។
   - ថ្ងៃសៅរ៍/អាទិត្យ/បុណ្យ៖ មានតែវេនយាម។
   - វេនយាមដែលគ្របម៉ោងគោល (ឧ. ២៤ម៉ោង ០៧:០០–០៧:០០) ជំនួសម៉ោងគោលថ្ងៃនោះ។
   - វេនយាមចាប់ផ្ដើមភ្លាមក្រោយល្ងាច (ក្នុង ៦០ នាទី)៖ អាចស្កេន **ចូលល្ងាច → ចេញព្រឹកស្អែក** ដោយមិនចាំបាច់ស្កេនចេញ/ចូលម៉ោង ១៧:០០។
   - ម៉ោងចេញពីវេនយាម ត្រូវបានគិតជាវត្តមានថ្ងៃចាប់ផ្ដើមវេន មិនមែនថ្ងៃបន្ទាប់ទេ។
   - សម្រាកក្រោយយាម៖ កំណត់ថ្ងៃបន្ទាប់ជា «ថ្ងៃឈប់» ក្នុងតារាងវេនយាម។ ប្រព័ន្ធបដិសេធវេនយាមដែលបញ្ចប់ក្រោយម៉ោងចូលធ្វើការថ្ងៃបន្ទាប់។
3. **ស្ថានភាពថ្ងៃ**៖ មានវត្តមាន / មកយឺត / ចេញមុន / មិនពេញលេញ (ខ្វះការស្កេនវគ្គណាមួយ រួមទាំងវេនយាម) / អវត្តមាន / ច្បាប់ / បេសកកម្ម / ថ្ងៃឈប់ / ថ្ងៃបុណ្យ។
4. **អនុគ្រោះ (grace)**៖ កំណត់នាទីអនុគ្រោះមកយឺត និងចេញមុន តាមម៉ោងធ្វើការនីមួយៗ។ លើសពីអនុគ្រោះ = គិតពេញចំនួននាទី។

## B. QR + Geofence Standard

1. QR ត្រូវ short expiry (ណែនាំ 1-5 នាទី)
2. បុគ្គលិកត្រូវនៅក្នុង geofence អង្គភាព
3. ប្រព័ន្ធត្រូវបង្ហាញ `Distance` និង `Allowed`
4. ប្រព័ន្ធត្រូវកាត់ duplicate scan ក្នុងពេលខ្លី

## C. Settings ត្រូវតែមាន

នៅ `App Setting`:

- `latitude`
- `longitude`
- `acceptable_range`

នៅ `Point Settings`:

- `attendance_start`
- `attendance_end`

នៅ `.env` (optional tuning):

- `ATTENDANCE_LATE_GRACE_MINUTES=10`
- `ATTENDANCE_EARLY_LEAVE_GRACE_MINUTES=10`
- `ATTENDANCE_REQUIRE_QR_TOKEN=true` (recommended សម្រាប់ production)

## D. Data Governance

1. Role/Permission ត្រូវច្បាស់
2. រាល់ការកែ attendance ត្រូវមាន audit trail
3. Reports ប្រចាំថ្ងៃត្រូវពិនិត្យ exceptions
4. Backup និង data retention ត្រូវមានផែនការ
